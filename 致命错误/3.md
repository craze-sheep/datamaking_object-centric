# 致命错误 3：剩余未解决问题 & 代码审查新发现

## 一、2.md 遗留：OOM / swap 耗尽（未解决，系统级）

### 现状

```text
Mem:   7.4GB 总计
Swap:  2.0GB，持续 100% 占用
```

Docker + Blender 渲染时，单个 Blender 进程约 1.6GB，加上 VSCode/Claude/Agent 等常驻进程，总内存远超 7.4GB，必然触发 OOM Kill。

### 为什么修复后风险更高

修复前：每个物理样本只创建 1 个 Blender renderer，复用渲染多个 view。
修复后：每个 view 创建一个独立 Blender renderer。

对于 S7/S8（默认 5 个 view），意味着一个物理样本会依次创建 5 个 Blender 实例（前一个 unlink 后 GC）。Blender 的 Python 内存释放不即时，峰值内存压力比修复前更大。

### 建议

短期（先做这个再跑数据）：
- Windows 侧 `.wslconfig` 加内存：
  ```ini
  [wsl2]
  memory=12GB
  swap=4GB
  ```
- 修改后 `wsl --shutdown` 重启 WSL2

长期（脚本端）：
- 每个 view 渲染完后显式 `import gc; gc.collect()`（已加入 task1 和 task6 的所有 Blender 渲染脚本）
- 或限制同时生成的样本数（`--samples_per_level` 分批跑）

## 二、代码审查新发现

### 2.1 kubric-main 被修改，依赖自定义 Cylinder

4 个文件被改动，全部为添加 `Cylinder` 支持：

| 文件 | 改动内容 |
|------|----------|
| `kubric-main/kubric/__init__.py` | 导出 Cylinder |
| `kubric-main/kubric/core/objects.py` | 定义 Cylinder 类 |
| `kubric-main/kubric/renderer/blender.py` | Blender `primitive_cylinder_add` 渲染 |
| `kubric-main/kubric/simulator/pybullet.py` | PyBullet `GEOM_CYLINDER` 碰撞形状 |

**影响**：S2(L7)、S3(L9)、S4(L8/L9)、S5(L9)、S6(L8)、S7(L8/L9)、S8(多处) 全部依赖 `kb.Cylinder`。如果切换到原始 Docker 镜像的 kubric（不带这些改动），这些脚本运行时会报 `AttributeError: module 'kubric' has no attribute 'Cylinder'`。

**建议**：确认 Docker 镜像中也挂载了这个修改版 kubric（当前 docker run 命令已挂载 `--volume ".../kubric-main:/kubric"`，所以容器内用的是修改版，没问题）。

### 2.2 S1 ObjectSpec 缺少 `height` 字段（已修复）

S1 的 ObjectSpec 没有 `height` 字段，`static_json` 硬编码 `"height": None`。S2-S8 都有 `height: float | None = None`。

功能上 S1 不使用 cylinder，所以无影响。但结构上不一致，如果将来 S1 需要加 cylinder 场景，会漏掉。

修复：S1 已补齐 `height: float | None = None`，`static_json` 改为输出 `spec.height`，与 S2-S8 的数据结构保持一致。

### 2.3 replay_scene_keyframes 在每个 view 都完整遍历（暂不优化）

`replay_scene_keyframes` 每次被调用都会遍历 scene 中所有 asset 的所有 keyframe 成员（position/quaternion/velocity/angular_velocity），每个 member 的每个 frame 都执行 setattr + keyframe_insert。

对于 S7/S8（5 view × 多物体），一轮物理仿真后 keyframe 被重放 5 次。功能上正确（idempotent），但第一次重放已经把 keyframe 写入了 Blender scene 的 F-curves，后续 4 次重放可以省略。

注意：暂不建议省略后续 view 的 `replay_scene_keyframes`。每个 view 都会创建新的 Blender renderer，新 renderer 会重新 link Kubric asset 到新的 Blender object；keyframe 需要重新通过 observer 通知到当前 renderer 对应的 Blender object 上。贸然跳过后续 replay，可能导致后续视角只拿到静态状态或缺少动画曲线。
