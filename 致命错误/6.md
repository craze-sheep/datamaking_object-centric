# 致命错误 6：Docker --restart + --overwrite 导致无限重跑

## 问题描述

给正在运行的容器添加 `--restart unless-stopped` 策略时，没有考虑到脚本使用了 `--overwrite` 参数。导致容器退出后自动重启，脚本从头覆盖重跑已完成的数据，形成无限循环。

## 根因分析

```bash
# 错误操作：给已有容器加 restart 策略
docker update --restart unless-stopped s3_dataset s8_dataset
```

脚本启动命令包含 `--overwrite`：
```bash
docker run -d --gpus all --name s3_dataset ... kubric-gpu \
  generate_s3_dataset.py --levels 1 2 3 4 5 6 7 8 9 --overwrite
```

组合效果：
1. 脚本跑完所有 level → 容器退出（exit 0）
2. `--restart unless-stopped` 自动重启容器
3. 脚本从头开始，`--overwrite` 删除已有数据重新生成
4. 无限循环

## 实际后果

- S3：已完成 2640 个样本（L1-L9），被重启后从头覆盖重跑
- S3 L3 被中断时少了 1 个样本（239/240）
- 浪费了数小时的 GPU/CPU 时间
- S8 同样受影响，但因尚未跑完，损失较小

## 教训

**`--restart` 和 `--overwrite` 绝对不能同时使用。**

添加 restart 策略前必须检查：
1. 脚本是否有 `--overwrite` 参数
2. 脚本是否有完成退出的行为（exit 0）
3. 两者同时存在 = 无限循环

## 修复

```bash
# 移除 restart 策略
docker update --restart=no s3_dataset s8_dataset

# 停止正在无限循环的容器
docker stop s3_dataset
```

## 状态

✅ 已修复 — restart 策略已从所有容器移除
