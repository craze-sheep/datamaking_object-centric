# 致命错误 1：多视角复用同一个 Blender renderer 导致 depth 大面积异常

## 结论

这是多视角 Kubric/Blender 渲染脚本的问题，不是数据读取问题。已生成数据中的直接损坏发生在 `task/task6-脚本编写` 产出的 S1/S2 depth；另外 `task/task1-判断相机视角/generate_five_view_kubric.py` 也存在同类 renderer 复用模式，虽然它只输出 rgba/segmentation、没有 depth，本次也按同一规则修正。

`S1` 和 `S2` 在一个物理样本内生成多个 view 时，代码只创建了一个 `Blender` renderer，然后在循环里不断切换 `scene.camera` 渲染不同视角。已生成数据表明：非 top 视角的深度图会大面积保留 Blender/Kubric 的远裁剪背景值，约 `1e10` 量级；top 视角正常。

## 我已复核的现象

### S1

`S1` 默认 views：

```python
default=["front", "top"]
```

输出 ID 分配方式：

- 同一个物理样本会输出两个目录。
- `output_start_id + 0` 是 `front`。
- `output_start_id + 1` 是 `top`。

实际数据检查结果：

- `S1` 共 `1600` 个样本。
- 深度正常 `800` 个，异常 `800` 个。
- 所有 `front` 样本异常：`800 / 800`。
- 所有 `top` 样本正常：`0 / 800` 异常。
- 因为默认顺序是 `front, top`，所以表现为所有奇数 ID 坏、所有偶数 ID 正常。

典型异常：

```text
database/S1/L1/1/1.npz
view: front
depth max: 11880463360.0
depth median: 10465321984.0
约 64% 像素 > 1e6
```

典型正常：

```text
database/S1/L1/2/2.npz
view: top
depth max: 8.003106117248535
无 > 1e6 的异常像素
```

### S2 交叉验证

`S2` 默认 views：

```python
default=["front", "top", "left"]
```

实际数据检查结果：

- `front`：`632 / 632` 异常。
- `left`：`631 / 631` 异常。
- `top`：`0 / 631` 异常。

前 6 个样本也完全吻合：

```text
S2/L1/1 view=front bad=True
S2/L1/2 view=top   bad=False
S2/L1/3 view=left  bad=True
S2/L1/4 view=front bad=True
S2/L1/5 view=top   bad=False
S2/L1/6 view=left  bad=True
```

这说明问题不是简单的奇偶 ID，而是和 view 类型/渲染顺序绑定；S1 的奇偶现象只是 `front, top` 两视角输出顺序造成的表象。

## 根因判断

强证据表明：同一个 `Blender` renderer 实例在多视角渲染中被复用时，切换 `scene.camera` 后 depth pass 没有按新视角稳定刷新，导致部分视角的背景/远处像素保留为约 `1e10` 的远裁剪值。

注意：segment mask 没有表现出同样问题。之前检查 S1 时，mask 的 shape、dtype、0/1 值域、`visible_area`、object id/frame id、同帧重叠关系都正常。问题集中在 depth。

## 修复建议

不要在多个 view 之间复用同一个 `Blender` renderer。

建议把 `Blender(...)` 的创建从 view 循环外移到循环内，让每个 view 使用独立 renderer 实例。因为物体动画 keyframe 是在仿真阶段写入的，如果 renderer 在仿真之后才创建，还必须把 scene 中已有 keyframe 重放给当前 renderer；每个 view 渲染完后也要把 renderer 从 scene 上 unlink，避免旧 renderer 继续作为 observer 留在 scene 上。

```python
for view_name, output_sample, sample_dir in view_outputs:
    renderer = Blender(
        scene,
        scratch_root / f"blender_{view_name}",
        adaptive_sampling=True,
        use_denoising=True,
        samples_per_pixel=args.samples_per_pixel,
    )
    try:
        replay_scene_keyframes(scene)
        rendered = render_view(...)
    finally:
        scene.unlink_view(renderer)
```

- `task/task1-判断相机视角/generate_five_view_kubric.py`
- `task/task6-脚本编写/generate_s1_dataset.py`
- `task/task6-脚本编写/generate_s2_dataset.py`
- `task/task6-脚本编写/generate_s3_dataset.py`
- `task/task6-脚本编写/generate_s4_dataset.py`
- `task/task6-脚本编写/generate_s5_dataset.py`
- `task/task6-脚本编写/generate_s6_dataset.py`
- `task/task6-脚本编写/generate_s7_dataset.py`
- `task/task6-脚本编写/generate_s8_dataset.py`

修复后必须重新生成受影响数据，至少包括：

- `S1` 所有 `front` 视角样本。
- `S2` 所有 `front` 和 `left` 视角样本。

如果要最稳妥，建议直接重新生成 `S1`、`S2`，避免目录里残留旧的异常 depth。

## 修复后的验收标准

重新生成后检查：

```text
depth.shape == (36, 128, 128)
depth.dtype == float32
np.isfinite(depth).all()
depth.max() 不应出现 1e10 量级
```

按 view 汇总时，`front/top/left` 都不应该再出现大面积 `> 1e6` 的像素。
