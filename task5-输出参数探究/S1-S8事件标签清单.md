# S1-S8 事件与标签清单

本文档只列“输出时应该记录什么”。输入采样参数仍按 task3 的各 `参数配置.md`。

## 全场景共享

所有 S 都记录：

- `sampled_params`：采样得到的输入配置。
- `objects[]`：物体几何、材质、质量、初始状态、角色。
- `cameras[]`：相机视角和输出路径。
- `events[]`：按时间排序的事件。
- `derived_labels`：由仿真和后处理得到的标签。
- `quality_checks`：有效性、出界、穿透、过滤原因。

共享事件：

- `ground_contact`
- `dynamic_dynamic_contact`
- `dynamic_static_contact`
- `stop`
- `leave_visible_area`
- `closest_approach`

共享派生标签：

- `final_positions`
- `final_velocities`
- `final_linear_speeds`
- `final_angular_speeds`
- `is_static_at_end`
- `visible_area_by_view`
- `left_visible_area_by_view`
- `contact_counts`
- `stress_sample`
- `sample_split`

## S1 落体/抛体

必须记录的输入重点：

- 释放高度：`initial_position.z` 或 `release_clearance`
- `initial_velocity`
- `radius` / `size`
- `mass`
- 物体和地面的 `restitution`
- `effective_restitution`

必须记录的事件：

- `first_ground_contact`
- `rebound_peak`
- `stop`
- `leave_visible_area`

派生标签：

- `first_contact_time`
- `first_contact_frame`
- `effective_restitution`
- `landing_position`
- `rebound_height`
- `max_height_after_release`
- `is_static_at_end`

记录理由：

- 落地时间要由仿真接触确定，不能只用理论公式。
- 尺寸无关性 level 比较的是底部离地高度，所以要记录 `release_clearance`。
- 反弹高度是恢复系数可见性的关键指标。
- restitution=0 的 Level 中 `rebound_height` 统一记录为 `0`；如果未发生落地接触或样本无效，则记录为 `null` 并在 `invalid_reason` 中说明。

## S2 水平地面滑动

必须记录的输入重点：

- `initial_velocity`
- `friction`
- `rollingFriction`
- `spinningFriction`
- `object_type`
- `mass`
- `size` / `radius` / `height`

必须记录的事件：

- `slide_start`
- `rolling_transition`
- `stop`
- `leave_visible_area`

派生标签：

- `stop_time`
- `stop_frame`
- `travel_distance`
- `displacement_vector`
- `final_position`
- `final_linear_speed`
- `final_angular_speed`
- `effective_lateral_friction`
- `rolling_transition_time`
- `is_static_at_end`

记录理由：

- 滑动距离和停止时间必须由轨迹计算。
- 球/圆柱的滚动转换需要角速度和平动速度共同判断。
- 质量、尺寸无关性需要成组样本的配对 id。

## S3 斜面滑动

必须记录的输入重点：

- `incline_angle`
- `ramp_s`
- `ramp_y`
- `ramp_surface_point`
- `ramp_normal`
- `friction`
- `rollingFriction`
- 初速度模式：`uphill` / `downhill` / `zero`

必须记录的事件：

- `slide_start`
- `rolling_transition`
- `ramp_bottom_reached`
- `stop`
- `leave_ramp`

派生标签：

- `slide_start_time`
- `slide_start_frame`
- `stop_time`
- `stop_frame`
- `travel_distance_on_ramp`
- `displacement_vector`
- `final_position`
- `final_linear_speed`
- `final_angular_speed`
- `effective_slope_acceleration`
- `effective_lateral_friction`
- `rolling_transition_time`
- `reached_ramp_bottom`
- `is_static_at_end`

记录理由：

- 斜面初始位置容易因公式错误造成微穿透，所以 ramp 几何中间量必须记录。
- 临界静止样本需要 `slide_start_time` 区分“没动”和“缓慢滑动”。

## S4 墙面反弹

必须记录的输入重点：

- 墙面位置、尺寸、法线方向。
- `incident_angle_degree`
- 物体和墙面 `restitution`
- 墙面 `friction`
- 物体 `initial_angular_velocity`
- cube 姿态：`face_contact` / `corner_contact`

必须记录的事件：

- `first_wall_contact`
- `ground_contact`
- `post_wall_rebound`
- `leave_visible_area`

派生标签：

- `first_wall_contact_time`
- `first_wall_contact_frame`
- `pre_collision_velocity`
- `post_collision_velocity`
- `incident_speed_normal`
- `reflected_speed_normal`
- `tangential_speed_before`
- `tangential_speed_after`
- `effective_restitution`
- `rebound_distance`
- `final_position`
- `final_linear_speed`
- `final_angular_speed`
- `is_static_at_end`

记录理由：

- 正碰/斜碰必须分解法向和切向速度。
- 墙是 static 物体，不能只看 dynamic-dynamic contact count。
- cube 边角碰撞需要记录姿态和角速度变化。

## S5 球撞球

- `impact_offset_y`
- `incident_angle_degree`
- 两球初始中心距和最近轨迹距离 `d_min`。

必须记录的事件：

- `first_ball_ball_contact`
- `closest_approach`
- `leave_visible_area`

派生标签：

- `first_contact_time`
- `first_contact_frame`
- `pre_collision_velocity_a`
- `pre_collision_velocity_b`
- `post_collision_velocity_a`
- `post_collision_velocity_b`
- `incident_speed_normal`
- `separation_speed_normal`
- `effective_restitution`
- `momentum_before`
- `momentum_after`
- `kinetic_energy_before`
- `kinetic_energy_after`
- `scattering_angle_a`
- `scattering_angle_b`
- `final_position_a`
- `final_position_b`

- 高速目标球出界是有效边界样本，需要可见性标签。

## S6 球撞方块

必须记录的输入重点：

- 球半径和方块尺寸。
- 方块姿态：`face_contact` / `yaw_22_5` / `yaw_45`。
- `impact_offset_y`
- `incident_angle_degree`
- 方块质量、恢复系数、摩擦。

必须记录的事件：

- `cube_rotation_after_contact`

派生标签：

- `first_contact_frame`
- `pre_collision_velocity_sphere`
- `pre_collision_velocity_cube`
- `post_collision_velocity_sphere`
- `post_collision_velocity_cube`
- `incident_speed_normal`
- `separation_speed_normal`
- `effective_restitution`
- `momentum_before`
- `momentum_after`

- `cube_rotation_angle`
- `scattering_angle_sphere`

- `final_position_cube`

- 多次反弹和二次接触必须保留完整序列，不能只记录第一次。

## S8 泛化负样本

必须记录的输入重点：

- `object_count`
- 每个动态物体类型、尺寸、质量、初始状态。
- 负样本原因：`negative_reason`
- `safety_margin`
- `projected_path_intersects`
- `time_gap_at_shared_region`
- 障碍物或墙的参数。
- 外部冲量：`intervention_time`、`target_object`、`impulse_vector`。

必须记录的事件：

- `closest_approach`
- `dynamic_static_contact`
- `wall_bounce`
- `external_impulse`
- `leave_visible_area`
- `would_collide_counterfactual`

派生标签：

- `object_count`
- `dynamic_object_types`
- `no_dynamic_collision`
- `total_dynamic_dynamic_contact_count`
- `total_dynamic_static_contact_count`
- `min_pairwise_distance`
- `min_pairwise_distance_frame`
- `closest_pair`
- `closest_approach_time`
- `closest_approach_frame`
- `relative_velocity_at_closest_approach`
- `projected_path_intersects`
- `time_gap_at_shared_region`
- `safety_margin`
- `initial_positions`
- `initial_velocities`
- `final_positions`
- `final_velocities`
- `final_linear_speeds`
- `final_angular_speeds`
- `is_static_at_end`
- `object_left_visible_area`
- `negative_reason`
- `counterfactual_would_collide`
- `stress_sample`
- `sample_split`

记录理由：

- S8 不能只写“无碰撞”，必须写清楚为什么无碰撞。
- 对随机负样本，要保存最近距离、最近帧和过滤原因。
- 对干预负样本，要保存反事实标签，否则无法说明“原本会撞但被冲量避开”。
- S8 L10 的 `stress_radius` 样本必须标记 `stress_sample=true` 且 `sample_split="stress"`，方便训练脚本默认排除或单独评估。

## 事件命名建议

统一命名，避免每个生成器写一套：

| 场景 | 推荐事件名 |
|---|---|
| 落体接地 | `first_ground_contact` |
| 墙面碰撞 | `first_wall_contact` |
| 两动态物体接触 | `dynamic_dynamic_contact` |
| 动态物体碰静态物 | `dynamic_static_contact` |
| 滑动开始 | `slide_start` |
| 停止 | `stop` |
| 滚动转换 | `rolling_transition` |
| 最近接近 | `closest_approach` |
| 离开可见区域 | `leave_visible_area` |
| 外部冲量 | `external_impulse` |

## 有效性过滤字段

每个 sample 都建议记录：

```json
{
  "quality_checks": {
    "valid_sample": true,
    "invalid_reason": null,
    "initial_overlap": false,
    "required_contact_sequence_satisfied": true,
    "unexpected_dynamic_contact": false,
    "min_visible_frames_by_object": {"ball_a": 36},
    "warnings": []
  }
}
```

对于无效样本，保留 metadata 也有价值，便于分析采样器为什么产生坏样本。
