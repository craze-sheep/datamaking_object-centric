# 文件路径设置

本文档设计两类路径：

1. `task5-输出参数探究/` 内部的文档与 schema 路径。
2. 未来正式生成数据集时的输出路径。

核心原则：**一个物理配置作为一个 sample，所有与它相关的 metadata、states、多视角视频、mask、depth 都放在同一个 sample 文件夹下。**

这样排错最方便：看到某个视频异常时，可以立刻在同目录找到生成参数、逐帧状态、事件标签和其他视角。

## 1. task5 文档目录结构

当前 task5 是设计阶段目录，不直接放大规模视频数据。建议结构如下：

```text
task5-输出参数探究/
  README.md
  输出参数记录规范.md
  S1-S8事件标签清单.md
  文件路径设置.md
  样例_metadata.json

  schema/
    metadata_schema.json
    states_schema.md
    manifest_schema.json

  examples/
    S1_falling_metadata.json
    S2_sliding_metadata.json
    S5_ball_ball_metadata.json
    S7_chain_metadata.json
    S8_negative_metadata.json

  notes/
    字段命名约定.md
    事件计算方法.md
    可见性与出界判定.md
    有效性过滤规则.md
```

各目录用途：

| 路径 | 用途 |
|---|---|
| `README.md` | task5 总入口，说明本目录解决什么问题 |
| `输出参数记录规范.md` | metadata、states、events、derived_labels 的字段规范 |
| `S1-S8事件标签清单.md` | 每个 S 场景应记录的事件和派生标签 |
| `文件路径设置.md` | 本文档，规定文件组织方式 |
| `样例_metadata.json` | 一个完整 metadata 示例 |
| `schema/` | 机器可校验或半机器可校验的 schema |
| `examples/` | 按场景拆开的 metadata 样例 |
| `notes/` | 计算方法、命名、过滤规则等补充说明 |

### 1.1 当前最小可用结构

现在不一定要一次性建立所有子目录。当前最小结构可以保持：

```text
task5-输出参数探究/
  README.md
  输出参数记录规范.md
  S1-S8事件标签清单.md
  文件路径设置.md
  样例_metadata.json
```

等后续开始写 schema 或更多样例时，再增加 `schema/`、`examples/`、`notes/`。

## 3. 为什么按 scene / level / sample 组织

推荐路径：

```text
samples/{scene_type}/{level_id}/{sample_id}/
```

原因：

- `scene_type` 对应 S1-S8，方便按任务类型查找。
- `level_id` 对应 task3 的 Level，方便按难度和物理规律筛选。
- `sample_id` 对应一个物理配置，多个相机视角共享同一套物理事件和逐帧状态。
- 同一个 sample 的所有文件聚合在一起，人工排查和自动质检都简单。

不建议采用这种分散结构：

```text
dataset_output/
  videos/
  metadata/
  states/
  masks/
```

原因：

- 同一个 sample 的文件被拆散，查问题需要跨目录拼路径。
- 删除坏样本时容易漏删某一类文件。
- 多视角共享同一个物理配置时，metadata 容易重复或不一致。
- 后续压缩、移动、抽样、人工复核都不方便。

## 4. sample_id 和 video_id 命名

### 4.1 sample_id

建议格式：

```text
{scene_code}_{level_id}_seed{seed:06d}
```

示例：

```text
S1_L1_seed000123
S5_L3_seed002581
S8_L10_seed010204
```

如果一个 seed 下会生成多个有效样本，可以增加 index：

```text
S8_L4_seed010204_idx003
```

### 4.2 video_id

建议格式：

```text
{sample_id}_{camera_view}
```

示例：

```text
S5_L1_seed000123_top
S5_L1_seed000123_front
S7_L10_seed000881_right
```

### 4.3 文件名

视频文件直接用视角名即可：

```text
videos/top.mp4
videos/front.mp4
```

因为它们已经位于 sample 文件夹内，不需要重复写 sample_id。

如果后续要把所有视频扁平化导出给训练脚本，再使用 `video_id.mp4`：

```text
flat_videos/S5_L1_seed000123_top.mp4
```

## 6. 全局 metadata.jsonl

`metadata.jsonl` 是索引文件，不替代每个 sample 下的 `metadata.json`。

建议路径：

```text
dataset_output/metadata.jsonl
```

每行建议是一条“单视角视频记录”，因为训练通常按视频读取：

```json
{
  "video_id": "S5_L1_seed000123_top",
  "physical_sample_id": "S5_L1_seed000123",
  "scene_type": "S5_球撞球",
  "level_id": "L1",
  "camera_view": "top",
  "video_path": "samples/S5_球撞球/L1/S5_L1_seed000123/videos/top.mp4",
  "metadata_path": "samples/S5_球撞球/L1/S5_L1_seed000123/metadata.json",
  "states_path": "samples/S5_球撞球/L1/S5_L1_seed000123/states.npz",
  "valid_sample": true,
  "first_contact_frame": 7,
  "object_count": 2
}
```

这样做的好处：

- 训练脚本可以只读 `metadata.jsonl` 快速获得视频路径。
- 需要详细标签时，再打开 sample 的 `metadata.json`。
- 一个物理 sample 的多个 view 会各占一行，方便按视角采样。

## 7. sample 内部文件

每个 sample 文件夹推荐：

```text
sample_000001/
  metadata.json
  states.npz
  videos/
  masks/
  depth/
  thumbnails/
  logs/
```

### 7.1 metadata.json

必须有。

记录：

- 全局配置
- 采样参数
- 物体属性
- 相机信息
- 事件列表
- 派生标签
- 质量检查
- 输出文件路径

### 7.2 states.npz

强烈建议有。

记录逐帧数组：

```text
positions:              [num_frames, num_objects, 3]
quaternions_wxyz:       [num_frames, num_objects, 4]
linear_velocities:      [num_frames, num_objects, 3]
angular_velocities:     [num_frames, num_objects, 3]
visible_area:           [num_frames, num_views, num_objects]
contact_matrix:         [num_frames, num_objects, num_objects]
dynamic_static_contact: [num_frames, num_objects]
```

### 7.3 videos/

按视角保存：

```text
videos/front.mp4
videos/top.mp4
videos/left.mp4
videos/right.mp4
videos/back.mp4
```

具体有哪些视角由 S 类型决定：

| 场景 | 视角 |
|---|---|
| S1 | front, top |
| S2 | front, top, left |
| S3 | front, top, left |
| S4 | front, top |
| S5 | front, back, left, right, top |
| S6 | front, back, left, right, top |
| S7 | front, back, left, right, top |
| S8 | front, back, left, right, top |

### 7.4 masks/

建议保存分割结果：

```text
masks/top_segmentation.npz
masks/front_segmentation.npz
```

用途：

- 计算物体 visible area。
- 判断出界、遮挡和小物体可见性。
- 支持后续 slot 相关任务。

### 7.5 depth/

建议保存深度：

```text
depth/top_depth.npz
depth/front_depth.npz
```

用途：

- 判断遮挡。
- 调试接触和穿透。
- 支持需要 depth 的后续实验。

### 7.6 thumbnails/

可选但很有用：

```text
thumbnails/top.png
thumbnails/front.png
```

用途：

- 快速人工浏览。
- 做质检报告。

### 7.7 logs/

可选：

```text
logs/generation.log
logs/warnings.json
```

用途：

- 保存渲染器 warning。
- 保存过滤器 warning。
- 排查失败样本。

## 8. split 文件

建议使用 sample 级 split，而不是 video 级 split。

路径：

```text
dataset_output/splits/
  train.json
  val.json
  test.json
  debug.json
```

每个 split 记录 `physical_sample_id` 列表：

```json
{
  "split": "train",
  "unit": "physical_sample",
  "sample_ids": [
    "S1_L1_seed000001",
    "S1_L1_seed000002",
    "S5_L3_seed000103"
  ]
}
```

原因：

- 同一个物理配置的不同视角不能同时出现在 train 和 test。
- 否则模型可能通过同一物理事件的另一个视角泄漏信息。

## 9. debug 子集

建议每次正式生成都维护一个小型 debug split：

```text
dataset_output/splits/debug.json
```

debug split 应包含：

- 每个 S 至少 2 个样本。
- 每个重要事件至少 1 个样本。
- 每个相机视角至少 1 个样本。
- 包含边界样本：出界、高速、低可见性、无碰撞近距离擦肩。

这样训练和数据读取脚本可以先用 debug split 快速验证。

## 10. invalid 样本如何存放

建议不要直接删除所有无效样本。可以单独放：

```text
dataset_output/invalid_samples/
  S5_球撞球/
    L6/
      S5_L6_seed000341/
        metadata.json
        states.npz
        logs/
```

无效样本不进入 `metadata.jsonl` 的默认训练索引，但保留它有价值：

- 分析采样器失败原因。
- 调整过滤规则。
- 复查仿真异常。

如果存储压力大，可以只保留 invalid metadata，不保留视频。

## 11. 临时文件和缓存

生成过程中可能有中间文件，建议放：

```text
dataset_output/_tmp/
dataset_output/_cache/
dataset_output/_logs/
```

约定：

- `_tmp/` 可以随时删除。
- `_cache/` 放资产缓存或渲染缓存，删除后可重建。
- `_logs/` 放全局生成日志，建议保留。

不要把临时帧 PNG 混进最终 sample 目录。

## 12. 路径记录规范

metadata 中所有路径建议使用相对 `dataset_output/` 的相对路径：

```json
{
  "video_path": "samples/S5_球撞球/L1/S5_L1_seed000123/videos/top.mp4",
  "metadata_path": "samples/S5_球撞球/L1/S5_L1_seed000123/metadata.json",
  "states_path": "samples/S5_球撞球/L1/S5_L1_seed000123/states.npz"
}
```

不建议在 metadata 中写绝对路径：

```text
/home/lzy/project/slot-datamaking/...
```

原因：

- 换机器后路径失效。
- 打包发布不方便。
- Docker 内外路径不同。

## 13. 中文路径与英文 id

可以保留中文场景目录：

```text
S5_球撞球/
```

但 id 建议使用 ASCII：

```text
S5_L1_seed000123
```

这样兼顾人读和程序处理：

- 人看目录知道场景含义。
- 程序处理 id 不受中文编码影响。

## 14. 最终推荐结构摘要

最推荐的正式结构：

```text
dataset_output/
  manifest.json
  metadata.jsonl
  splits/
    train.json
    val.json
    test.json
    debug.json
  samples/
    {scene_type}/
      {level_id}/
        {sample_id}/
          metadata.json
          states.npz
          videos/
            {view}.mp4
          masks/
            {view}_segmentation.npz
          depth/
            {view}_depth.npz
          thumbnails/
            {view}.png
          logs/
            warnings.json
  invalid_samples/
    {scene_type}/
      {level_id}/
        {sample_id}/
          metadata.json
          states.npz
          logs/
  _tmp/
  _cache/
  _logs/
```

这套结构的关键点：

- 以物理 sample 聚合所有文件。
- 用 `metadata.jsonl` 做全局训练索引。
- 用 sample 级 split 防止多视角数据泄漏。
- 保留 invalid 样本的 metadata 用于改进采样器。
- 所有路径在 metadata 中使用相对路径。
