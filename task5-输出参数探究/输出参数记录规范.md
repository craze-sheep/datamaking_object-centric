# 输出参数记录规范

## 1. 总体结构

每个物理配置可以渲染多个相机视角。建议把“物理配置”和“视频视角”分开记录：

```text
sample_id/
  metadata.json          # 必须：物理配置、相机、标签、质量检查
  states.npz             # 可选但强烈建议：逐帧位置/速度/接触
  videos/
    front.mp4
    top.mp4
    ...
```

如果后续为了训练方便改成 JSONL，也建议保持同样字段：

```text
metadata.jsonl           # 每行一个 video/view 或一个 physical sample
```

推荐粒度：

- `physical_sample_id`：同一个物理配置共享一个 id。
- `video_id`：`physical_sample_id + camera_view`。
- `scene_type`：S1-S8。
- `level_id`：Level 1、Level 2 等。
- `camera_view`：front/top/left/right/back。

## 2. 必须记录的全局字段

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `schema_version` | string | 人工指定 | 例如 `slot-datamaking-meta-v1` |
| `physical_sample_id` | string | 生成器 | 物理配置唯一 id |
| `video_id` | string | 生成器 | 单视角视频唯一 id |
| `scene_type` | string | 生成器 | `S1_落体` 等 |
| `level_id` | string | 生成器 | `L1`、`L2` |
| `level_name` | string | 生成器 | level 中文名 |
| `random_seed` | int | 生成器 | 复现采样 |
| `duration_s` | float | 配置 | 目前 3.0 |
| `fps` | int | 配置 | 目前 12 |
| `num_frames` | int | 配置 | 目前 36 |
| `resolution` | list[int] | 配置 | 目前 `[64,64]`，探针视频可不同 |
| `gravity` | list[float] | 配置 | `[0,0,-9.8]` |
| `units` | object | 固定 | m / kg / s / m/s / rad/s |
| `engine` | object | 生成器 | Kubric、PyBullet、Blender、版本、Docker image |

## 3. 物体属性需要记录什么

每个物体放在 `objects[]` 中。动态物体、静态地面、墙、斜面、障碍物都要记录。

### 3.1 身份与几何

| 字段 | 是否必须 | 说明 |
|---|---:|---|
| `object_id` | 必须 | 视频内唯一，如 `ball_a`、`cube_b`、`ground` |
| `object_type` | 必须 | `sphere`、`cube`、`cylinder`、`ramp`、`wall` |
| `static` | 必须 | true/false |

### 3.2 几何参数

| 物体 | 必须字段 |
|---|---|
| sphere | `radius` |
| cube/wall/ground/ramp | `size` |
| cylinder | `radius`、`height` |
| ramp | `incline_angle`、`ramp_s`、`ramp_y`、`ramp_normal` |

### 3.3 材质与动力学参数

| 字段 | 说明 |
|---|---|
| `mass` | static 物体也记录，但标注 static 时 mass 不参与动力学 |
| `friction` | 动态物体表面摩擦；sphere/cube/cylinder 等物体按 task3 参数配置使用该字段 |
| `lateralFriction` | 地面、墙、斜面、障碍等静态接触面摩擦；ground/ramp/wall 按 task3 参数配置使用该字段 |
| `rollingFriction` | 滚动摩擦 |
| `spinningFriction` | 自旋摩擦 |
| `restitution` | 恢复系数 |

### 3.4 初始状态

每个动态物体必须记录：

- `initial_position`
- `initial_quaternion`
- `initial_velocity`
- `initial_angular_velocity`

姿态统一使用 Kubric 文档中的 `[w,x,y,z]`。如果 PyBullet 内部用 `[x,y,z,w]`，metadata 里也要保存 Kubric 格式，并可附加 `engine_quaternion_xyzw` 作为调试字段。

### 3.5 视觉属性

必须记录：

- `color_name`
- `rgba`
- `visible_area_by_view`
- `left_visible_area_by_view`

可见性字段的来源需要写清楚：

- `visible_area_source="segmentation"`：由 segmentation mask 计算，最准确。
- `visible_area_source="projected_bbox"`：由投影 AABB 估算，适合不保存 mask 的主训练样本。
- `visible_area_source="not_computed"`：未计算时必须显式标注，不能默默缺省。

原因：task3 中有高速出界样本，不能只靠标签判断视频是否还能被模型看见。

## 4. 相机需要记录什么

每个 view 放在 `cameras[]` 中：

| 字段 | 说明 |
|---|---|
| `view_name` | front/top/left/right/back |
| `position` | 世界坐标 |
| `look_at` | 世界坐标 |
| `quaternion` 或 `rotation_matrix` | 二选一 |
| `focal_length` / `fov` | 按渲染器可用字段记录 |
| `resolution` | 单视角分辨率 |
| `video_path` | 相对路径 |
| `segmentation_path` | 若输出 mask |
| `depth_path` | 若输出 depth |

建议额外输出：

- segmentation mask：用于验证物体可见性。
- depth：用于遮挡、出界和接触可见性排查。

存储策略：

- `videos/` 和 `metadata.json` 必须保存。
- `states.npz` 强烈建议保存，至少 debug/invalid 样本必须保存。
- segmentation mask 不要求所有主训练样本永久保存；建议 debug split、invalid 样本、低可见性/stress 样本、质检抽样保存。
- depth 不要求所有样本保存；建议复杂遮挡、墙/障碍、debug split 和质检抽样保存。
- 如果不保存 mask/depth，metadata 里的对应路径写 `null`，并记录 `visible_area_source` 的替代计算方式。

## 5. 事件需要记录什么

事件放在 `events[]`，每个事件都用统一结构：

```json
{
  "event_type": "dynamic_dynamic_contact",
  "time": 0.5833,
  "frame": 7,
  "objects": ["ball_a", "ball_b"],
  "position": [0.12, 0.0, 0.22],
  "normal": [1.0, 0.0, 0.0],
  "pre_velocity": {"ball_a": [1.8,0,0], "ball_b": [0,0,0]},
  "post_velocity": {"ball_a": [0.1,0,0], "ball_b": [1.7,0,0]}
}
```

事件分类：

| 类别 | event_type |
|---|---|
| 接触 | `ground_contact`、`wall_contact`、`dynamic_dynamic_contact`、`dynamic_static_contact` |
| 运动状态 | `slide_start`、`rolling_transition`、`stop`、`leave_visible_area` |
| 轨迹关系 | `closest_approach`、`shared_region_crossing`、`path_intersection_without_contact` |
| 干预 | `external_impulse` |
| 过滤 | `invalid_initial_overlap`、`missed_required_contact`、`unexpected_dynamic_contact` |

事件要求：

- 所有事件同时记录 `time` 和 `frame`。
- 接触事件必须记录对象对、接触法线、接触点、碰前/碰后速度。
- 同一视频允许多个事件，按时间排序。
- 连锁碰撞必须保留完整 `contact_pair_sequence`。

## 6. 派生标签需要记录什么

派生标签放在 `derived_labels` 中。它们不是采样参数，而是由仿真轨迹、接触事件或后处理计算得到。

通用标签：

| 字段 | 说明 |
|---|---|
| `final_positions` | 每个动态物体最后一帧位置 |
| `final_velocities` | 每个动态物体最后一帧速度 |
| `final_linear_speeds` | 速度模长 |
| `final_angular_speeds` | 角速度模长 |
| `is_static_at_end` | 末帧是否静止，需定义速度阈值 |
| `object_left_visible_area` | 是否离开可视/地面范围 |
| `contact_counts` | 接触统计；区分新接触、持续/resting 接触和总接触，避免地面 resting contact 把计数冲得很大 |
| `valid_sample` | 是否通过该 level 的过滤条件 |
| `invalid_reason` | 若无效，写清楚原因 |

建议阈值：

- `static_linear_speed_threshold`: `0.03 m/s`
- `static_angular_speed_threshold`: `0.05 rad/s`
- `contact_time_tolerance`: `1 / fps`
- `visible_area_min_frames`: 按 task3 约束，离开前至少 12 帧可见时可作为边界样本保留。

## 7. 逐帧状态怎么记录

`metadata.json` 记录摘要；`states.npz` 或 `states.hdf5` 记录逐帧状态。

建议 arrays：

```text
positions:              [num_frames, num_objects, 3]
quaternions_wxyz:       [num_frames, num_objects, 4]
linear_velocities:      [num_frames, num_objects, 3]
angular_velocities:     [num_frames, num_objects, 3]
visible_area:           [num_frames, num_views, num_objects]
contact_matrix:         [num_frames, num_objects, num_objects]
dynamic_static_contact: [num_frames, num_objects]
```

逐帧状态好处：

- 能重新计算 first_contact_time、stop_time、closest_approach。
- 能检查过滤器是否误判。
- 能支持后续不同任务读取不同标签。

## 8. 推荐记录文件格式

### 必须：metadata JSON

优点：可读、可 diff、适合单样本排错。

### 大规模索引：JSONL / Parquet

将每个 metadata 的摘要展开为一行，方便训练前筛选：

- `scene_type`
- `level_id`
- `video_id`
- `camera_view`
- `object_count`
- 主变量字段
- 关键事件时间
- `valid_sample`
- `video_path`

### 逐帧：NPZ / HDF5

训练不一定直接使用，但生成阶段强烈建议保存或至少保留调试版。

## 9. 不建议遗漏的字段

最容易漏但后面会痛的字段：

- `random_seed`
- `engine` 和版本
- `camera_view`
- `static`
- `contact_pair_sequence`
- `effective_restitution`
- `visible_area_by_view`
- `visible_area_source`
- `stress_sample`
- `sample_split`
- `invalid_reason`
- 原始采样参数和派生标签的区分字段：`sampled_params` vs `derived_labels`

## 10. 记录责任划分

| 阶段 | 负责记录 |
|---|---|
| 采样器 | sampled_params、objects 初始属性、相机、seed |
| 物理仿真 | states、contact events、final states |
| 后处理 | first_contact、stop、closest_approach、visible-area、valid_sample |
| 渲染器 | video_path、depth、segmentation、camera matrices |
| 质检脚本 | invalid_reason、warning、人工抽检结果 |
