# 数据集构成

本数据集用于让模型学习物理常识和因果推导。第一版只做无机器人、无机械臂、无主动外力的数据，物体运动来自初始速度、重力、斜面、墙面、摩擦、反弹和碰撞。

每个物理样本组生成 5 个同步视角视频：前、后、左、右、上。5 个视频共享同一次仿真的物体属性、初始状态、轨迹和碰撞事件，只改变相机方向。

---

## 1. 全局设置

| 项目 | 数值 |
|------|------|
| 渲染分辨率 | `256 x 256` |
| 帧数 | `36` 帧 |
| 帧率 | `12 fps` |
| 视频时长 | `3 s` |
| 物理步进 | `240 Hz` |
| 重力 | `(0, 0, -9.81)` |
| 地面 | `Cube(scale=(4.0, 4.0, 0.08), position=(0, 0, -0.08))` |
| 默认地面摩擦 | `0.3` |
| 默认地面恢复系数 | `0.5` |
| 场景中心 | `(0, 0, 0)` |

坐标约定：

| 轴 | 含义 |
|----|------|
| `x` | 左右方向 |
| `y` | 前后方向 |
| `z` | 高度方向 |

## 4. 属性取值

### 4.1 物理属性桶

| 属性 | 低 | 中 | 高 |
|------|----|----|----|
| 质量 `mass` | `0.5` | `1.0` | `2.0` |
| 摩擦 `friction` | `0.10` | `0.40` | `0.80` |
| 恢复系数 `restitution` | `0.10` | `0.50` | `0.85` |

### 4.2 材质属性

| 材质 ID | metallic | roughness | 默认 friction | 默认 restitution | 默认 mass 系数 |
|---------|----------|-----------|----------------|-------------------|----------------|
| `metal` | `1.0` | `0.2` | `0.4` | `0.3` | `2.7 * size^3` |
| `rubber` | `0.0` | `0.7` | `0.8` | `0.7` | `1.1 * size^3` |
| `matte` | `0.0` | `0.9` | `0.5` | `0.2` | `1.0 * size^3` |

第一版中，为了方便控制因果变量，优先直接使用 `mass/friction/restitution` 三个显式数值桶；材质只作为外观标签保存。

## 6. 扩展场景构成

前 8 个场景是可控基础物理集。为了不浪费 `kubric-main/场景` 中已有资源，扩展部分继续加入 KuBasic 复杂几何体、MOVi 多物体、GSO 真实物体、PyBullet URDF 物体、遮挡和复杂杂物场景。

机器人、机械臂、夹爪、车辆和四足机器人暂时不作为本数据集物体，因为它们会引入主动控制外力，不符合当前“无外部主动干预”的设定。

## 9. 磁盘空间估算

当前完整版本：

```text
3,318 个物理样本组
16,590 个 5视角视频
每个视频 36 帧
分辨率 256 x 256
总帧数 597,240 帧
```

### 9.1 不保存 RGB 的版本

当前计划不保存 RGB，只保存：

- `segmentation`
- `depth`
- `forward_flow`
- `backward_flow`
- `camera`
- `instances`
- `states`
- `visibility`
- `events.collisions`
- `view_id`
- `scenario_id`

其中属性、状态、相机和事件信息以 JSON/NPZ 等结构化文件保存，空间相对较小，主要空间来自 mask、depth 和 float32 光流。

### 9.2 保存 mask + depth + float32 光流

如果保存 `segmentation + depth + forward_flow + backward_flow`，按未压缩数组粗略估算：

| 内容 | 数据格式 | 完整版空间 |
|------|----------|------------|
| segmentation | `uint16`, 1通道 | 约 78 GB |
| depth | `uint16`, 1通道 | 约 78 GB |
| forward/backward flow | `float32`, 2通道 x 2 | 约 626 GB |
| 合计 | 不含 RGB | 约 783 GB |

### 9.3 全部物体属性和状态估算

这里的“属性”不只是物体类别，还包括所有物体的静态属性、每帧状态、每视角可见性、bbox、相机参数和碰撞事件。

按完整版本 `S1-S16` 估算：

```text
物理样本组数量：3,318
估算总物体实例数：约 14,610
平均每个样本组物体数：约 4.4
```

估算时包含：

| 内容 | 字段示例 | 估算空间 |
|------|----------|----------|
| 物体静态属性 | shape, scale, color, material, mass, friction, restitution, is_dynamic | 约 15 MB |
| 每帧 3D 状态 | position, quaternion, velocity, angular_velocity | 约 27 MB |
| 每视角可见性和框 | visibility, image_position, bbox | 约 74 MB |
| 相机参数 | camera position, quaternion | 约 17 MB |
| 碰撞事件 | frame, instances, force, position, normal | 约 32 MB |
| 合计 | compact NPZ/JSONL 估算 | 约 165 MB |

如果使用缩进 JSON、重复字段名、每个样本单独保存多个文件，实际可能放大到 `0.5-2 GB`。即使保守预留，属性和状态数据建议按 `5 GB` 计算即可。

所以当前“不保存 RGB”的完整版本总量可以按：

```text
mask + depth + float32 flow：约 783 GB
全部物体属性/状态/事件：建议预留 5 GB
合计：约 788 GB
```

### 9.4 推荐预留空间

| 保存方式 | 建议预留磁盘 |
|----------|--------------|
| mask + depth + float32 flow + 全部属性 | `900 GB - 1.2 TB` |
| 再保留少量预览 RGB MP4 | `1.0 - 1.3 TB` |
| 还保存 Blender 临时文件、scene state、调试帧 | `1.5 TB` 更稳 |

如果先生成基础可控版 `S1-S8`，规模是 `9,180` 个视频、`330,480` 帧：

| 保存方式 | 基础版空间 |
|----------|------------|
| mask + depth + float32 flow + 属性 | 约 `433 GB` 未压缩 |
| 推荐预留 | `500-700 GB` |
