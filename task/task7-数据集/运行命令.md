# S1-S8 数据集运行命令

以下命令从项目根目录运行：

```bash
cd /home/lzy/project/slot-datamaking
```

默认使用 GPU 渲染，并禁止写入 Python bytecode，避免多个容器同时 import 公共脚本时写 `__pycache__`：

```bash
-e KUBRIC_USE_GPU=True \
-e KUBRIC_GPU_BACKEND=OPTIX \
-e PYTHONDONTWRITEBYTECODE=1
```

如需重新生成并覆盖已有输出，在脚本参数末尾追加：

```bash
--overwrite
```

## S1 落体

Levels: `1 2 3 4 5 6 7`

```bash
docker run -d --gpus all \
  --name s1_dataset \
  --user $(id -u):$(id -g) \
  -e KUBRIC_USE_GPU=True \
  -e KUBRIC_GPU_BACKEND=OPTIX \
  -e PYTHONDONTWRITEBYTECODE=1 \
  -v "/home/lzy/project/slot-datamaking:/workspace" \
  -v "/home/lzy/project/slot-datamaking/kubric:/kubric" \
  -w /workspace \
  kubric-gpu \
  task/task6-脚本编写/generate_s1_dataset.py --levels 1 2 3 4 5 6 7
```

## 并行运行注意事项

可以并行运行不同的 S 任务，例如 S1 和 S2，因为它们分别写入 `database/S1/...` 和 `database/S2/...`。

不要并行运行会写入同一批输出目录的命令，例如两个 S2 都使用默认 `--start_id 1` 且生成同一个 level。尤其不要让两个任务同时带 `--overwrite` 覆盖同一个 `database/S{scene}/L{level}/{sample_id}`。

每个容器必须使用不同的 `--name`。如果同名容器已经存在，先 `docker rm` 已停止容器，或换一个新名字。

如果 `KUBRIC_GPU_BACKEND=OPTIX` 在当前环境里报错，把它改成 `KUBRIC_GPU_BACKEND=CUDA`。

## 查看进度

查看某个任务日志：

```bash
docker logs -f s2_dataset
```

查看运行中的容器：

```bash
docker ps
```

查看 GPU：

```bash
docker exec s2_dataset nvidia-smi
```

停止某个任务：

```bash
docker stop s2_dataset
```

删除已停止的同名容器后重跑：

```bash
docker rm s2_dataset
```
