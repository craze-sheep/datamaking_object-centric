# Kubric 可用场景整理
> 目标：梳理当前 `kubric-main` 仓库里可以直接复用或改造的数据生成场景，帮助后续构建“物理规则交互视频数据集”，尤其是球体、方块、碰撞、滑动、相机运动、实例分割和事件标注类任务。

---

## 1. 总览

Kubric 是一个合成数据生成框架，核心能力是用 **PyBullet 做物理仿真**，用 **Blender 做渲染**，并自动导出丰富标注。当前仓库可用场景主要分三类：

| 类别 | 代表脚本/目录 | 是否有物理交互 | 主要用途 | 推荐程度 |
|------|---------------|----------------|----------|----------|
| 简单示例场景 | `examples/*.py` | 有/部分有 | 快速理解 Kubric API、调试渲染和标注 | 高 |
| MOVi 多物体视频 | `challenges/movi/*` | 强 | 多物体刚体运动、碰撞、分割、深度、光流、轨迹 | 最高 |
| 视觉挑战数据集 | `challenges/*/worker.py` | 视任务而定 | NeRF、重建、抠图、光流、点跟踪、材质泛化 | 中到高 |

对于“机械臂推小球碰撞方块”这类项目，最值得优先参考的是：

1. `examples/mini_physics_showcase.py`：已有自由落体、斜面滑动、碰撞迁移三类简洁物理场景，容易改造成小球碰撞方块。
2. `examples/bouncing_balls.py`：俯视2D弹球风格，适合做碰撞推理、slot/object tracking 的快速原型。
3. `challenges/movi/movi_ab_worker.py`：CLEVR风格基础几何体，适合做可控形状/颜色/材质的多物体碰撞。
4. `challenges/movi/movi_c_worker.py` 和 `movi_def_worker.py`：真实扫描物体、HDRI背景、更复杂相机和物体数，适合扩展到更真实的数据集版本。

## 2. 基础示例场景

### 2.1 `examples/helloworld.py`

**定位**：Kubric 入门渲染示例。

**场景特点**：
- 简单物体、相机和光源。
- 用来确认 Docker/Kubric/Blender 环境能否跑通。
- 适合做最小 sanity check，不适合直接当物理数据集模板。

**适用场景**：
- 第一次验证 Kubric 安装。
- 检查输出目录、渲染文件、基础标注是否正常。

---

### 2.2 `examples/basic.py`

**定位**：不依赖高级 Bullet/Blender 流程的简单 API 示例。

**场景特点**：
- 构建一个简单 scene：地面、球、光源、相机。
- 更像 Kubric 对象系统教学。

**适用场景**：
- 学习 `kb.Scene`、`kb.Cube`、`kb.Sphere`、`kb.PerspectiveCamera` 等基础对象。
- 适合作为自定义场景脚本的骨架。

---

### 2.3 `examples/bouncing_balls.py`

**定位**：俯视角 2D 弹球式物理碰撞。

**场景特点**：
- 正交相机从上往下看，近似2D平面运动。
- 默认 4 个球，支持球/方块/混合形状。
- 可设置 `restitution`、`friction`、球半径、颜色采样方式。
- 会输出图像、分割、metadata 和碰撞事件。

**关键参数**：

| 参数 | 含义 | 默认值 |
|------|------|--------|
| `--min_nr_balls` / `--max_nr_balls` | 球/物体数量范围 | 4 / 4 |
| `--ball_radius` | 半径 | 0.15 |
| `--restitution` | 恢复系数 | 1.0 |
| `--friction` | 摩擦系数 | 0.0 |
| `--shape` | `sphere`、`cube`、`mixed` | `sphere` |
| `--color` | 颜色采样策略 | `uniform_hsv` |

**适用场景**：
- 碰撞检测、反事实推理、轨迹预测。
- 快速验证 object-centric 模型和 slot 模型。
- 可以作为 CLEVRER 风格碰撞视频的低成本原型。

**示例命令**：

```bash
docker run --rm --interactive \
  --user $(id -u):$(id -g) \
  --volume "$(pwd):/kubric" \
  kubricdockerhub/kubruntu \
  /usr/bin/python3 examples/bouncing_balls.py \
  --min_nr_balls=3 \
  --max_nr_balls=6 \
  --shape=mixed \
  --restitution=0.8 \
  --friction=0.05
```

---

### 2.4 `examples/mini_physics_showcase.py`

**定位**：项目里最贴近“物理规则视频数据集”的自定义小型展示脚本。

**已有场景**：

| 场景名 | 脚本内 key | 物理事件 | 说明 |
|--------|------------|----------|------|
| 自由落体反弹 | `free_fall` | bounce | 球体下落、撞击地面、反弹 |
| 斜面滑动 | `ramp_slide` | slide | 方块从斜面滑下 |
| 碰撞迁移 | `collision` | collision | 蓝色球碰撞黄色球，发生动量传递 |

**输出内容**：
- `rgb.mp4`：RGB视频。
- `segmentation_color.mp4`：彩色分割视频。
- `presentation_preview.png`：预览图。
- `labels.json`：场景标签、物体属性、碰撞事件摘要、事件标签。
- `manifest.json`：全部样本索引。

**为什么适合本项目**：
- 已经有物体属性标签：质量、摩擦、恢复系数、形状、代理形变标签。
- 已经有事件摘要：接触次数、首次物体-物体碰撞、首次地面接触。
- 比 MOVi 更轻，改成“推球撞方块”很容易。

**示例命令**：

```bash
python examples/mini_physics_showcase.py -- \
  --output_dir output/mini_physics_showcase \
  --resolution 192 \
  --num_frames 36 \
  --samples 32 \
  --scenarios free_fall ramp_slide collision
```

**建议改造方向**：
- 新增 `robot_push_ball` 场景：用一个 kinematic cube/机械臂末端替代真实机械臂，推动球体。
- 新增 `ball_hits_block` 场景：球体初速度由推杆赋予，目标是撞击静止方块。
- 新增事件标签：`push_start`、`push_end`、`ball_block_collision`、`block_displacement`。

## 3. MOVi 系列多物体视频场景

MOVi 是 Kubric 最重要的多物体视频数据集系列。每个样本通常是 **2秒刚体仿真**，默认 12fps、24帧，输出 RGB、深度、光流、法线、object coordinates、实例分割、物体位姿、速度、角速度、碰撞事件等。

### 3.1 MOVi-A：CLEVR 风格基础几何体

**脚本**：`challenges/movi/movi_ab_worker.py`

**生成配置**：

```bash
/usr/bin/python3 challenges/movi/movi_ab_worker.py \
  --objects_set=clevr \
  --background=clevr \
  --camera=clevr
```

**场景特点**：
- 灰色地面、固定风格相机、简单灯光。
- 3-10个随机物体。
- 物体来自 CLEVR 风格三种形状：cube、sphere、cylinder。
- 两种大小、两种材质、八种颜色。

**适合用途**：
- 最适合做可控物理推理数据集第一版。
- 适合复现 CLEVRER 风格物体属性和碰撞事件。
- 视觉复杂度低，便于模型聚焦在物理和因果关系上。

---

### 3.2 MOVi-B：扩展基础几何体

**脚本**：`challenges/movi/movi_ab_worker.py`

**生成配置**：

```bash
/usr/bin/python3 challenges/movi/movi_ab_worker.py \
  --objects_set=kubasic \
  --background=colored \
  --camera=random
```

**场景特点**：
- 在 MOVi-A 基础上增加更多几何形状，如 cone、torus、gear、teapot、suzanne 等。
- 相机从半球壳随机采样。
- 物体颜色和背景颜色更随机。
- 物体 scale 在连续范围内采样。

**适合用途**：
- 用于测试模型对形状、颜色、尺度、相机角度变化的泛化。
- 比 MOVi-A 更复杂，但仍然是干净的几何体场景。

---

### 3.3 MOVi-C：真实扫描物体 + HDRI 背景

**脚本**：`challenges/movi/movi_c_worker.py`

**生成配置**：

```bash
/usr/bin/python3 challenges/movi/movi_c_worker.py \
  --camera=fixed_random
```

**场景特点**：
- 物体来自 Google Scanned Objects。
- 背景使用 Poly Haven HDRI，HDRI 同时作为背景、地面和光照。
- 3-10个随机真实物体。
- 支持 train/test 对象和背景划分。

**适合用途**：
- 从几何体过渡到真实物体外观。
- 测试模型对真实纹理、复杂形状、自然光照的鲁棒性。
- 适合做 sim-to-real 前的中间难度版本。

---

### 3.4 MOVi-D：更多物体 + 静动态混合

**脚本**：`challenges/movi/movi_def_worker.py`

**生成配置**：

```bash
/usr/bin/python3 challenges/movi/movi_def_worker.py \
  --camera=fixed_random
```

**场景特点**：
- 10-20个静态物体。
- 1-3个动态物体被抛入场景。
- 标注中包含 `is_dynamic`，可区分初始静止物体和动态物体。

**适合用途**：
- 多物体遮挡、静动态分离、复杂接触链。
- 测试模型是否能处理大量不运动但可被碰撞影响的物体。

---

### 3.5 MOVi-E：线性相机运动

**脚本**：`challenges/movi/movi_def_worker.py`

**生成配置**：

```bash
/usr/bin/python3 challenges/movi/movi_def_worker.py \
  --camera=linear_movement
```

**场景特点**：
- 在 MOVi-D 基础上加入简单线性相机运动。
- 相机从半球壳采样起点，并在视频中以恒定速度移动。
- 相机始终看向场景中心。

**适合用途**：
- 动态相机下的物体分割、深度、光流、点跟踪。
- 更接近真实机器人头部/外部相机移动的观测。

**扩展版本**：

```bash
/usr/bin/python3 challenges/movi/movi_def_worker.py \
  --camera=linear_movement_linear_lookat \
  --max_camera_movement=8.0
```

该配置对应 panning MOVi-E，适合训练/评估点跟踪模型。

---

### 3.6 MOVi-F：运动模糊 + 高分辨率光流

**脚本**：`challenges/movi/movi_def_worker.py`

**生成配置**：

```bash
/usr/bin/python3 challenges/movi/movi_def_worker.py \
  --camera=linear_movement \
  --max_motion_blur=2.0
```

**场景特点**：
- 基本等同 MOVi-E。
- 增加随机运动模糊。
- 原始渲染分辨率为 512x512，并提供 256x256/128x128 下采样版本。

**适合用途**：
- 光流预测。
- 动态相机 + 运动模糊下的鲁棒视觉感知。

## 4. 其他视觉挑战场景

### 4.1 Optical Flow Prediction

**目录**：`challenges/optical_flow`

**核心来源**：MOVi-F。

**用途**：
- 训练或评估光流预测模型。
- 适合需要 forward/backward flow 标注的任务。

---

### 4.2 Point Tracking

**目录**：`challenges/point_tracking`

**场景特点**：
- 基于 MOVi-E 的 `object_coordinates`、深度、相机姿态和物体位姿生成长期点轨迹。
- 提供 `dataset.py` 作为点跟踪数据生成/演示入口。

**用途**：
- TAPIR/CoTracker 类点跟踪任务。
- 长期可见性、遮挡、再出现的跟踪评测。

---

### 4.3 Multi-view Object Matting

**脚本**：`challenges/multiview_matting/worker.py`

**场景特点**：
- ShapeNet 前景物体。
- Poly Haven 室内 HDRI 背景。
- 物体放在随机颜色桌面上。
- easy 模式单显著前景物体，hard 模式增加 clutter。
- 多视角拍摄同一个前景物体。

**用途**：
- 多视角前景抠图。
- 单物体重建前的分割/遮罩质量评估。

---

### 4.4 Single View Reconstruction

**脚本**：`challenges/single_view_reconstruction/worker.py`

**场景特点**：
- 基于 ShapeNetCoreV2。
- 55类物体，总计约 51,300 个模型。
- 每个模型从 24 个随机视角渲染。
- 输出相机位姿和类别标签。

**用途**：
- 单图3D重建。
- 视角泛化、类别泛化。

---

### 4.5 Video Based Reconstruction

**脚本**：`challenges/video_based_reconstruction/worker.py`

**可选物体**：

```text
cube, torus, car, airplane, chair, table, pillow
```

**场景特点**：
- 面向单目视频3D重建。
- 支持刚体 ShapeNet 物体和非刚性人物动画。
- 可选择是否旋转相机、是否添加外部纹理、是否移除纹理。
- 输出格式适配 LASR，包括图像、mask、光流、相机参数。

**示例命令**：

```bash
/usr/bin/python3 challenges/video_based_reconstruction/worker.py \
  --object=car \
  --rotate_camera=True
```

---

### 4.6 Texture and Structure in NeRF

**脚本**：`challenges/texture_structure_nerf/worker.py`

**场景特点**：
- 随机放置多个形状。
- 使用程序纹理，并按纹理频率分 band 标注。
- 输出 JAXNeRF 可用格式：`train/val/test` 图像、segmentation、相机 transforms。

**关键参数**：

| 参数 | 含义 |
|------|------|
| `--num_objects` | 物体数量，默认30 |
| `--num_frequency_bands` | 纹理频率分段数，默认6 |
| `--num_train_frames` | 训练视角数，默认60 |
| `--num_validation_frames` | 验证视角数，默认60 |
| `--num_test_frames` | 测试视角数，默认60 |

**用途**：
- NeRF 中纹理和几何结构解耦研究。
- 不适合物理交互，但适合材质/纹理泛化。

---

### 4.7 Robust NeRF

**脚本**：`challenges/robust_nerf/worker.py`

**场景特点**：
- 静态场景中加入非静态干扰物。
- 包含 teleport 和 jitter 两类挑战思想：随机出现/结构性抖动的 outlier。
- 默认可生成较长序列，脚本默认 `frame_end=301`、12fps、256x256。

**用途**：
- 测试 NeRF 对非静态异常物体的鲁棒性。
- 可借鉴“动态干扰物”思想，用于构造机器人场景中的干扰碰撞/遮挡。

---

### 4.8 Complex BRDF

**脚本**：`challenges/complex_brdf/worker.py`

**场景特点**：
- ShapeNet 物体。
- 24个视角。
- 重点在高反射/非 Lambertian 材质。
- 对比 specular 与 lambertian 场景。

**用途**：
- 材质泛化、镜面反射、少视角 novel view synthesis。
- 不适合做物理碰撞，但适合给物体材质增加难度。

---

### 4.9 ShapeNet Renders for Pre-Training

**脚本**：`challenges/pretraining_visual/worker.py`

**场景特点**：
- ShapeNet 物体。
- 每个物体 25 个随机视角。
- 透明背景，512x512，裁剪到物体。
- 55 个 ShapeNet 类别标签。

**用途**：
- 视觉表征预训练。
- 单物体分类、形状识别、视角鲁棒性。

## 5. Kubric 常见输出标注

不同 worker 输出略有差异，但 MOVi 和物理场景通常可以导出：

| 标注 | 含义 | 对物理视频数据集的价值 |
|------|------|------------------------|
| `video` / `rgba` | RGB或RGBA视频 | 模型输入 |
| `segmentation` | 实例分割ID | object-centric学习、mask监督 |
| `depth` | 深度图 | 3D感知、遮挡推理 |
| `forward_flow` / `backward_flow` | 光流 | 运动估计、点跟踪 |
| `normal` | 表面法线 | 3D几何理解 |
| `object_coordinates` | 物体坐标系下的点坐标 | 点跟踪、可见性、3D对应 |
| `instances.positions` | 每帧3D位置 | 轨迹预测 |
| `instances.quaternions` | 每帧姿态 | 旋转/姿态预测 |
| `instances.velocities` | 每帧速度 | 动力学学习 |
| `instances.mass` | 质量 | 物理属性推理 |
| `instances.friction` | 摩擦系数 | 滑动/停止预测 |
| `instances.restitution` | 恢复系数 | 弹性碰撞推理 |
| `events.collisions` | 碰撞帧、碰撞对象、力、位置、法线 | 因果链、事件检测、问答标注 |

这些标注非常适合构造类似 CLEVRER 的问题：

```text
描述性：哪个物体首先发生碰撞？
解释性：是什么导致黄色方块开始移动？
预测性：2秒后蓝色球会不会碰到墙？
反事实：如果球的恢复系数降低，方块是否还会移动？
属性推理：哪个物体质量更大？
```

## 6. 面向“机械臂推球碰撞方块”的推荐路线

### 阶段一：快速原型

基于 `examples/mini_physics_showcase.py` 新增 `robot_push_ball`：

| 元素 | 实现建议 |
|------|----------|
| 机械臂末端/推杆 | 先用 kinematic cube 或 cylinder 代替真实机械臂 |
| 被推物 | sphere，小球 |
| 目标物 | cube 或 cylinder |
| 动作 | 推杆按关键帧平移，接触小球 |
| 事件 | 推杆-球接触、球-方块碰撞、方块位移 |
| 标注 | 物体属性、动作参数、碰撞事件、终态位置 |

优点是最容易跑通闭环：生成视频、分割、属性、事件和问答。

### 阶段二：CLEVR/MOVi 风格规模化

基于 `challenges/movi/movi_ab_worker.py`：

- 保留 CLEVR 风格简单物体。
- 增加一个主动运动物体或推杆。
- 控制球、方块、障碍物数量。
- 系统改变质量、摩擦、恢复系数、初速度、相机角度。
- 自动生成事件图和问答。

### 阶段三：真实外观和复杂背景

基于 `movi_c_worker.py` / `movi_def_worker.py`：

- 替换为 GSO 真实物体。
- 使用 HDRI 背景和自然光照。
- 加入动态相机。
- 加入更多静态干扰物和遮挡。
- 保留 held-out objects/backgrounds 作为 OOD 测试。

### 阶段四：机器人 embodiment

Kubric 本身更偏视觉/物理数据生成，不是完整机器人仿真平台。若一定要做真实机械臂结构，有两条路线：

1. **轻量路线**：用几何体推杆代理机械臂末端，重点训练物理因果和碰撞推理。
2. **重路线**：导入机器人 URDF/mesh，或转向 SAPIEN/MuJoCo/Isaac Sim 生成机器人控制数据，再用 Kubric 风格导出视觉和标注。

对当前项目，建议先走轻量路线，把数据集 schema、事件标注和问答生成稳定下来。

## 7. 推荐优先级

| 优先级 | 场景 | 原因 |
|--------|------|------|
| P0 | `examples/mini_physics_showcase.py` | 已有碰撞、滑动、弹跳和事件标签，最容易改 |
| P0 | `examples/bouncing_balls.py` | 低成本碰撞推理原型 |
| P1 | MOVi-A | CLEVR风格基础几何体，适合可控变量 |
| P1 | MOVi-B | 更多形状和相机随机性 |
| P2 | MOVi-C | 真实物体和HDRI背景 |
| P2 | MOVi-D/E/F | 多物体、动态相机、运动模糊 |
| P3 | Point Tracking / Optical Flow | 作为附加评测任务 |
| P3 | NeRF/重建/抠图类场景 | 与物理碰撞主线关系较弱，可后续扩展 |

---

## 8. 一句话结论

Kubric 里最适合本项目的“可用场景”不是 NeRF 或重建类挑战，而是 **mini physics showcase + bouncing balls + MOVi-A/B/C/D/E** 这条路线：先从简洁可控的球/方块碰撞做起，再逐步增加真实物体、HDRI背景、多物体遮挡和动态相机。
